## 1. เป้าหมายของโครงการ

พัฒนาระบบติดตามสภาพ Compressor Module ของเครื่อง HT-9046MX จำนวน 19 เครื่อง เครื่องละไม่เกิน 8 โมดูล โดยใช้ข้อมูล pressure, temperature, expansion-valve command และ control state ตามเวลา

เป้าหมายระยะใกล้คือ:

- ตรวจว่าพฤติกรรมปัจจุบันเบี่ยงจาก baseline ของเครื่อง–โมดูล–สถานะนั้นหรือไม่
- ตรวจ drift และ dynamic response ที่ผิดจากอดีต
- สร้างคำเตือนพร้อมหลักฐานให้ช่างตรวจสอบ
- รองรับเครื่องใหม่หรือเครื่องหลังซ่อมด้วย Auto-bootstrap ที่ควบคุมความเสี่ยง

เป้าหมายระยะยาวถัดไปคือ supervised binary anomaly model หลังมี technician confirmations ที่ผ่าน QA เพียงพอ ระบบนี้ไม่ใช่ PLC control, safety interlock หรือเครื่องมือยืนยัน leak อัตโนมัติ

ข้อตกลง UX/label ล่าสุด: Health/Condition Score ใช้บอก `Normal within this profile` ได้เฉพาะเมื่อ data/profile gate ผ่านและไม่พบ persistent anomaly; ไม่ใช่ failure probability. สำหรับ alert ใหม่หลัง prospective-feedback boundary ช่างเลือกเพียง `EQUIPMENT_ANOMALY`, `NO_EQUIPMENT_ANOMALY` หรือ `UNRESOLVED`; ไม่มี cause, action หรือ refrigerant field. Live API ต้องมี IANA timezone ที่ยืนยันแล้วสำหรับ `detected_at` ซึ่งเป็น MySQL `DATETIME(6)` ก่อนเทียบ boundary มิฉะนั้นจะ fail closed. เฉพาะ yes/no ที่ผ่าน Label QA ใช้สร้าง binary supervised dataset ในภายหลัง; note เป็น audit context ไม่ใช่ class.

Auto-bootstrap ส่วน Server มีโค้ดพร้อมแล้ว: source MySQL แบบ read-only → profile candidate ต่อ machine/module/SV/qualified state → forward-only shadow 3 วัน → registry และกราฟสีเขียว/แดงให้ approver ตรวจ. เขียว/แดงหมายถึง deviation ต่ำกว่า/เกิน candidate threshold ไม่ใช่เปอร์เซ็นต์หรือ diagnosis. Worker ไม่ approve เอง; Reject เก็บ active เดิมและรอข้อมูลใหม่ก่อน retry, Approve เปลี่ยน active pointer แบบ transactional พร้อม rollback mode. ยังไม่มีการเชื่อม Server หรือสร้าง active profile จริง.

## 8. Model architecture ที่ตัดสินใจใช้

```text
Ingest and schema/unit/time validation
→ Data and operating-state gate
→ Local robust calibration ต่อ machine/module/state/SV
→ Relative, pressure-differential, slope and event-response features
→ One-sided CUSUM/EWMA + ARX residual + Isolation Forest
→ Evidence fusion and threshold calibration
→ Persistence หลาย window/cycle/day
→ Technician-facing alert
→ Maintenance verification and label feedback
```

### Four-evidence architecture (system direction; not yet a new live release)


| มิติ | คำถามที่ระบบตอบ | ตัวอย่างหลักฐาน |
|---|---|---|
| Self | ค่านี้ต่างจาก baseline ของตัวเองหรือไม่ | robust z-score, quantile, local residual |
| Dynamic | การตอบสนองหลัง valve/control เปลี่ยนต่างจากปกติหรือไม่ | ARX residual, lag, gain, settling |
| Peer | ต่างจาก peer ที่อยู่ในบริบทเทียบได้หรือไม่ | conditional peer residual, coverage, multivariate deviation |
| Temporal | เป็น transient หรือค้าง/เปลี่ยน trend ต่อเนื่อง | EWMA, CUSUM, slope, changepoint, persistence |


บทบาทของโมเดล:

| ระดับข้อมูล | โมเดลหลัก | Challenger |
|---|---|---|
| ปัจจุบัน ไม่มี confirmed labels | Robust baseline, CUSUM/EWMA, ARX residual, Isolation Forest | PCA-SPE, ECOD/COPOD, One-Class SVM |
| Normal sequence ครบหลาย state/event | Shallow hybrid เดิม | TCN-AE, LSTM encoder-decoder |
| มี confirmed labels จำนวนน้อย | Anomaly screening + human review | Extra Trees/CatBoost แบบ cost-sensitive |
| Labels และ coverage เพียงพอ | Calibrated supervised tree + anomaly fallback | Physics-guided/sequence classifier |


Parameter direction ที่ยังต้อง tune ด้วย validation:

- Isolation Forest: ทดลองหลาย seed, `n_estimators` ระดับหลายร้อย, จำกัด `max_samples`, แยก model score ออกจาก alert threshold
- CUSUM: tune reference shift `k`, decision threshold `h` และ persistence จาก false-alert budget
- ARX/Ridge: minute lag 1–10; one-second lag 1–30 พร้อมทดลอง delay 5–120 วินาที
- TCN-AE: kernel 3, dilation 1/2/4/8/16/32, channels 16–32 เป็น starting grid
- LSTM-AE: 1–2 layers, hidden size 32/64 เป็น starting grid

ค่าข้างต้นเป็น experiment range ไม่ใช่ production parameter

Deep Research v1.1 เพิ่ม model challengers และข้อกำกับต่อไปนี้: ECOD/COPOD, RRCF, Matrix Profile, nested temporal HPO, range/event metrics, dependent-data conformal calibration, weak supervision และ production ML testing/monitoring โดยยังคงหลักว่า simple/statistical baseline ต้องถูกเปรียบเทียบภายใต้ข้อมูลและ outer test เดียวกับ deep model ทุกครั้ง รายละเอียดและแหล่งอ้างอิงอยู่ใน `THESIS.md` และ `research/claim-to-source-ledger.md`.

ต้องรองรับ `INSUFFICIENT_DATA`, `INSUFFICIENT_COVERAGE`, `REVIEW_REQUIRED`, `REJECTED`, `SUPERSEDED` และ `ROLLBACK_ACTIVE`

- quarantine extreme residual, persistent anomaly และช่วงใกล้ service transition
- หาก quarantine กระจุกต่อเนื่อง ให้หยุดที่ `REVIEW_REQUIRED`

## 10. Validation และ metric contract

ลำดับ validation ที่ต้องใช้:

```text
Past-only temporal split
→ Leave-one-machine-out
→ Sparse/new-machine external test
→ Service-epoch holdout
→ Shadow production replay
```

ข้อกำหนด:

- overlapping windows จาก cycle/event เดียวกันต้องอยู่ split เดียวกัน
- baseline, scaler, imputer, feature selection, model และ threshold ต้อง fit จาก training period เท่านั้น
- future-derived 30/120-second features ต้องมี availability time และ purge/embargo ที่เหมาะสม
- uncertainty ใช้ block/cluster bootstrap ระดับ cycle หรือ machine-day ไม่สุ่มรายวินาที
- HPO ใช้ inner temporal/group validation; threshold/persistence ใช้ calibration block; outer test ต้อง untouched
- รันหลาย seed และรายงาน median ควบคู่ worst-machine result

ก่อนมี labels ให้รายงาน flag rate, alerts per machine-day, persistence, score drift, seed stability, LOMO dispersion และ worst-machine behavior

หลังมี QA-approved binary labels จึงเพิ่ม precision, recall, PR-AUC, false alerts per machine-day, missed faults, lead time และ probability calibration ของ binary anomaly model
